# 某同类开源模块的代码质量审计与自研决策

- 审计对象：某同类开源模块（面向 HyperOS 的 LSPosed 隐私模块），2026-11-26 的 2.0.4 版本
- 规模：Java 约 8,400 行 / 25 个文件；主界面类约 2,500 行，自绘底栏约 1,000 行
- 许可证：GPL-3.0
- 方式：静态审阅（未在真机运行）。

## 结论

**建议独立实现，不 fork、不直接使用。** 该模块的价值在于「HyperOS 各组件在采集什么、从哪个域名上报」这份调研成果（规则文档与默认配置表），而不是代码本身。

理由：

1. 架构底座有缺陷：配置通道、签名身份、网络拦截层都需要推倒重来，修补成本高于重写。
2. 默认值激进且与自身文档矛盾，装上即改变多个系统组件的行为。
3. 存在已确认的功能性 bug（拦截根本没挂上、递归、超时失效、导入损坏）。
4. 约一半代码是界面层（约 4,300 / 8,400 行），其中自绘底栏与开关约 1,200 行，与隐私功能无关，却占维护成本大头。
5. GPL-3.0：复制其代码即须整体以 GPL-3.0 发布。独立实现时只参考域名与行为清单（事实信息），不复制实现。

## 已确认的问题

### 严重

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | 配置写入全局系统设置 | 通过 root shell 把全部开关与自定义规则写入全局设置项 | 任意应用无需权限即可读取，可据此检测模块存在、读出全部开关与自定义规则。隐私工具本身成为指纹源。libxposed API 100+ 已提供远程偏好，无需 root、不外泄 |
| 2 | 签名私钥入库 | 调试密钥库（口令为公开默认值）提交在仓库，CI 用它签发正式版本 | 任何人可签出同签名 APK 覆盖安装，继承 root 管理器按 uid 授予的 root 与 LSPosed 作用域（21 个应用，含系统组件与输入法） |
| 3 | 默认值与文档矛盾 | 文档写明某设备认证类规则「默认关闭（影响远程认证、查找设备）」；实际默认开启，且无条件拦截查找设备相关的云端主机 | 默认安装即可能影响设备认证与查找设备 |

### 高

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 4 | 短信拦截从未生效 | 三个短信发送方法的签名均写错（参数个数与类型不符，列表类型也不对） | 按签名查找方法抛异常后只在日志记一条「未命中」，用户无从得知 |
| 5 | IPv6 字面量导致递归 | 解析 IP 字面量的辅助函数调用了已被自身拦截的地址解析接口 | 严格模式（统计类规则默认开启）下遇到 `::1`、`fe80::` 等会反复重入直至栈溢出，本地 IPv6 被误拦 |
| 6 | 网络拦截仅在 Java 层且覆盖面窄 | 只拦截少数几个 Java 网络入口 | 自带网络库 / 原生网络库直接绕过；路径规则只在其中一个入口生效，主流 HTTP 客户端的路径规则全部失效 |
| 7 | root 超时失效 | 先阻塞读取标准输出到 EOF，再等待 20 秒超时 | 授权弹窗未处理或命令卡住时线程永久阻塞，20 秒超时形同虚设 |
| 8 | 配置同步竞态 | 每次切开关新起线程执行 root 写入，热重载固定延迟 600 ms 后触发 | 线程乱序时旧快照可能最后写入导致开关丢失；root 写入慢于 600 ms 时热重载读到旧配置 |
| 9 | 导入配置损坏自定义规则 | 导出时原样读取已编码的规则，导入时未解码直接写回，同步时再编码一次 | 每导入一次，自定义规则多编码一层 |
| 10 | 热重载可能清空全部拦截 | 先卸载所有旧拦截，若此时取不到当前应用上下文就直接返回、不重装 | 开启自动热重载时，模块更新后部分进程的保护静默消失 |

### 中

- **大范围启发式替换**：按类名扫描 DEX 后批量替换方法。对两款第三方输入法的统计包，除少数前缀外的所有非 native `void` 方法都被置空；安装器的广告标识兜底会命中相关类中任意 ≤2 参数的 `String` 方法。误伤不可预测。
- **启动开销**：安全中心单次注入扫描最多 2×8,000 个类，安装器 3×2,500，统计服务最多 20,000（所用的类枚举接口已被官方弃用）。
- **硬编码混淆名**：直接调用混淆后的 AIDL 回调与单字母类名，换个 ROM 版本即失效或错挂。
- **拦截回调不兜异常**：直接返回空值（空游标、空显示对象、空标识），调用方没有判空时会让系统应用崩溃。
- **共享可变返回值**：应用列表查询等接口每次返回同一个列表实例，调用方修改会互相污染；新版系统的参数重载未覆盖。
- **SQL 子串匹配**：拦截任何包含表名子串的数据库语句，可能阻断数据库迁移。
- **自定义「类名#*」规则**：在系统进程中把整类方法替换为默认值，且规则来源是可被持有安全设置写入权限的应用篡改的全局设置。

### 工程

- 无 Gradle、无 XML 布局、无依赖锁定；CI 下载 build-tools 与 android.jar 均不校验哈希，android.jar 下载失败时回落到 API 16 的 Maven 桩包。
- 由 `pull_request` 触发的工作流拥有 `contents: write`。
- 测试只覆盖 shell 转义与日志格式化，配置解析、规则匹配、拦截逻辑零覆盖。
- 主界面是约 2,500 行的上帝类；销毁时不移除回调与服务监听，后台线程销毁后仍 Toast。
- 多语言用映射表、以中文整句为键，约 30 处 Toast 未覆盖。
- 注释与实现不符：配置加载处注释称「查询本应用的只读 provider，不写系统设置」，实际读写全局设置；类头注释称拦截侧只用默认值。
- 仓库 2026-11-06 创建，已有 79 份版本说明（`1.0.1` → `2.0.4`），补丁版本密集，反映规则靠真机试错迭代。

## 做得好的部分（值得借鉴）

- 每个注入阶段独立 `try/catch`，单个拦截点失败不影响其他。
- 伪造值考虑兼容性：IMSI 保留真实 MCC+MNC，MAC 返回 `02:00:00:00:00:00` 而非 `null`。
- 规则文档区分了「纯遥测」与「关闭会影响功能」的端点，是很有价值的调研资料。
- 用脚本校验作用域列表、处理表与界面分组三者一致。
- 利用新版 API 热重载，改开关后无需重启目标进程。

## 自研方案要点

| 方面 | 该模块 | 自研 |
|---|---|---|
| 配置通道 | 全局系统设置 + root | libxposed 远程偏好（界面写、拦截侧只读监听），不需要 root |
| 签名 | 私钥入库 | 私钥仅存 CI Secret |
| 网络拦截 | 少数 Java 入口 | 首选按 uid 的系统级网络策略，覆盖原生代码；需要按路径拦截时再在应用进程内的多个网络层分别设防 |
| 方法拦截 | DEX 全量扫描 + 启发式 | 只用公开 SDK 入口与框架 API；按 ROM 版本声明式规则表，命中失败即上报「未生效」 |
| 默认值 | 激进全开 | 只默认开启「纯遥测、无功能影响」的规则；其余需用户确认（后来补充了对高风险数据的默认阻止，并写明影响） |
| 安全护栏 | 回调不兜底 | 每个拦截回调统一兜异常，失败时放行，宁可漏拦不崩溃 |
| 可验证性 | 界面显示开关状态 | 显示真实挂载结果（已生效 / 未生效 / 不适用），便于发现签名写错一类问题 |
| 构建 | 手写脚本 | Gradle + 版本锁定；规则匹配、配置解析、IP 判定写单元测试 |
| UI | 手写 Canvas | 标准组件（Compose 或 Preference），不做装饰性动效 |

### 首版范围（按价值/风险排序）

1. 系统分析服务整进程断网（纯遥测，风险最低）
2. 厂商统计 SDK 的上报接口置空（公开入口，跨多个系统应用通用）
3. 运营商 / 厂商遥测域名
4. 系统广告：开屏、应用商店与安装器广告域名
5. 设备标识伪造（IMEI / Android ID / MAC / 序列号），仅对作用域内应用
6. 输入法统计域名（只拦统计，不碰云输入）

### 不复刻

- 设备认证相关规则与查找设备云端主机：影响设备认证与查找设备
- 混淆回调、数据库辅助类启发式置空、数据库语句子串拦截
- 输入法 SDK 的 `void` 方法批量置空
- 任意「类名#*」自定义规则
- root 删除安全中心的检测数据库文件
