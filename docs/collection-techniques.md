# 应用是怎么收集隐私数据的：科普与 HyperPrivacy 的应对

这是一篇科普性质的概览，面向想了解「手机里的数据是怎么被收集的」的普通用户。它不是技术手册，只讲大方向；具体的防护范围见 [防护范围与规则覆盖](privacy-surface.md)。文中各节的「应对」描述的是能力方向，实际覆盖范围以应用内的规则列表与版本说明为准。除系统应用外，从 0.4 起也可以按应用保护你自己安装的应用。

## 为什么系统开关和权限还不够

Android 这些年不断收紧隐私：限制设备序列号、MAC 地址、应用列表，位置、通讯录、短信都要用户授权。这些措施很有价值，但并不完整：

- **开关只管「自己那一份」。** 关掉某个系统的「用户体验计划」，只是告诉对应的功能别再上报，并不保证其他组件、其他 SDK 也跟着停。
- **权限只管「读什么」，不管「怎么绕」。** 有些信息并不经过权限检查，比如系统里任何应用都能读的设置项、共享存储里的文件、逐个询问「某个应用装没装」。
- **数据的出口很多。** 即使一个出口被堵住，应用还可能换一条网络路径、换一种网络库，甚至从服务器临时下载一段新代码。

所以「把权限关好」是必要的，却不是全部。下面按类别看看常见的收集方式。

## 一、设备标识

应用想认出「这是同一台手机」，会收集各种标识：IMEI、序列号、MAC 地址、Android ID、广告标识（OAID 等）、DRM 设备 ID，也会读取系统属性、`/proc` 与 `/sys` 下的硬件信息，再把它们拼成一个「设备指纹」。

平台对其中很多标识已经加了限制，但限制往往只挡住「标准接口」。厂商自定义的设置项、系统属性或文件，有时仍然可以被普通应用读到；一些 SDK 还会借助反射等手段去调用被隐藏的接口。单个标识的信息量也许不大，组合起来就足以长期追踪一台设备。

**HyperPrivacy 的应对**

- 向第三方应用返回「限制广告追踪」形式的全零广告标识，小米自家服务不受影响。
- 在系统层向第三方应用隐藏账号与设备标识类的设置项。
- 让不同应用读到互不相同的 DRM 设备 ID，使各应用之间无法借它相互关联。
- 可按应用开启「随机化硬件指纹」（默认关闭）：让不同应用读到互不相同的部分免权限硬件特征值，降低跨应用设备关联风险，常规功能与机型信息保持正常。
- 对系统应用里已确认的设备标识上报通道，按规则拦截。

## 二、已安装应用列表

一台手机里装了哪些应用，能反映职业、收入、健康状况、兴趣等。Android 11 之后，应用不能随意枚举全部应用，但仍有几条路：声明「查询全部应用」权限，利用启动器入口的宽泛声明看到大部分应用，或者拿着一份包名清单逐个询问「这个装了吗」。此外，一些系统组件会把应用列表写进其他应用可读的设置项，或在应用安装、卸载时增量上报。

**HyperPrivacy 的应对**

- 精确拦截系统应用中已确认的应用列表上报通道。
- 在系统层收紧「逐个探测」，让第三方应用无法借此拼出完整的应用列表，并可由用户按应用选择：哪些应用看不到你装了什么（常用的社交、分享与支付类应用默认仍可见，可开启严格模式一并隐藏）。
- 隐藏系统设置里泄露应用列表的条目。
- 默认对第三方应用隐藏本模块自身。

## 三、使用行为

应用可以通过「使用情况访问」「无障碍服务」「通知监听」了解你用了什么、在什么时候用、屏幕上显示了什么；输入法也知道你在哪个应用里打字；剪贴板里常有验证码、链接和口令。这些能力大多需要你主动授权，但名字听起来都很普通，常被「省电」「清理」之类的功能顺带索要。

**HyperPrivacy 的应对**

- 拦截系统应用中已确认的行为统计与日志通道；对你选中的第三方应用，拦截其内置统计 SDK 的上报。
- 系统自带的剪贴板读取提示、应用行为记录等功能已经做得不错，HyperPrivacy 不重复建设，建议配合使用。
- 汇总并提示哪些应用拥有这类高影响力的授权，让你清楚「谁有能力」，由你决定是否保留。

## 四、没有位置权限，也能知道你在哪

位置并不只来自 GPS。Wi-Fi 与基站信息、蓝牙信标、照片里的位置信息，都能用来推算位置；服务器还可以根据 IP 地址判断你所在的城市，这一步完全不需要手机授权。另外，当你因为天气等功能授予过位置权限后，同一个 SDK 也可能共用这份授权，在后台继续采集。

**HyperPrivacy 的应对**

- 拦截系统应用中已确认的位置采集与统计上报，同时保留天气、定位查询、查找设备这类你主动使用的服务。
- 受限于原理，按 IP 的粗略定位无法在手机端阻止，需要你自行取舍。

## 五、通讯录、短信与通话记录

这三类数据最为敏感。除了直接申请权限读取，也有一些旁路：输入法能看到你输入的手机号与验证码，无障碍服务能读取短信界面，通知监听能读取短信通知。此外，部分运营商功能会通过数据短信发送设备信息。

**HyperPrivacy 的应对**

- 默认拦截通讯录、短信原文与短信链接等高风险上报通道，并在规则里写明可能的副作用。
- 对确实会影响功能的规则，交由你自行决定是否开启。

## 六、网络层的各种绕行

收集到数据之后，需要发送出去；而许多传统拦截手段，正是在这里被绕过的：

- **隐藏主机名。** 上报地址被拆开、编码或加密，普通的字符串扫描找不到。
- **HTTPDNS / DoH。** 应用绕过系统 DNS，自行向某个解析服务查询，再直接连接 IP。依赖「按域名拦截」的 hosts 与 DNS 方案对此无能为力。
- **写死的 IP 直连。** 完全不需要域名解析。
- **自带网络栈。** 应用内置 QUIC 或原生网络库，不使用系统的网络实现。
- **共用服务器与长连接。** 上报和正常业务共用同一个域名，或夹带在推送长连接里，粗暴封堵会误伤正常服务。
- **加密与重试。** 内容加密后无法从抓包中看出端倪；被拦截后还会排队重试。

**HyperPrivacy 的应对**

- 在应用进程内的多个网络环节同时设防（域名解析、TLS 握手、HTTP 客户端、内嵌网页），按「域名加路径」精确到接口，同一服务器上的正常服务照常工作。
- 对只做上报的系统应用，在系统层按应用整体断网，不依赖 VPN，也不占用 VPN 通道。
- 对第三方应用可强制使用系统 DNS，阻止它绕开系统去问第三方解析服务，让上述域名规则看得见真实的目的地。
- 对推送等必需通道不做拦截，宁可保留也不影响你收到消息。

## 七、代码层的绕行

- **运行时下载代码。** 应用安装时看起来很干净，运行后才从服务器下载一段新代码，上报逻辑只存在于这段代码里；热修复与插件化框架也有类似效果。
- **SDK 重打包与混淆。** 把类名、包名改写成无意义的字符，使按名称识别 SDK 的工具失效。
- **原生代码。** 把关键逻辑放进 C/C++ 库，绕开 Java 层的各类检查。
- **云端开关。** 采集项由服务器下发，可能装好几天之后才启用，也可能只对一部分设备开启。

**HyperPrivacy 的应对**

- 拦截基于运行时的实际行为，而不是仅依赖静态的名字，因此对混淆有一定抵抗力。
- 对你安装的应用，离线识别其中内置的追踪 SDK；广告 SDK 按请求与页面的发起来源拦截，不依赖域名，SDK 换域名、改包名或以插件形式加载时同样有效。无法归类的疑似广告组件会单独列出，由你决定。
- 诊断模式可观察到运行时才出现的新通道，帮助发现和补充规则。

## 八、跨应用关联与唤醒链

- **跨应用标识。** 同一家公司或同一个 SDK 的多个应用，会把同一个 ID 存在大家都能访问的位置，比如共享存储里的隐藏文件或系统设置项，用它把你在不同应用里的行为关联起来。
- **家族应用互通。** 同一厂商的应用通过导出的组件互相交换设备 ID；同一签名的应用还会拿到同一个 Android ID。
- **唤醒链。** 推送 SDK 在一个应用被唤醒时，顺带拉起集成了同一 SDK 的其他应用，使它们得以在后台继续运行并上报。

**HyperPrivacy 的应对**

- 在系统层对第三方应用隐藏可被跨应用读取的标识类条目，并通过应用列表收紧减少「彼此发现」的机会。
- 唤醒管理主要由 HyperOS 自带的关联启动与自启动管理负责，HyperPrivacy 不重复建设。

## 边界：模块做不到的事

HyperPrivacy 运行在系统与应用的框架层，有明确的能力边界，以下情况可能无法完全覆盖：

- **原生与自建网络栈。** 部分完全由原生代码实现或自建加密传输的网络路径可能无法被完全覆盖。
- **底层设备特征。** 部分无需权限即可读取的系统与硬件细微特征难以彻底消除，模块仅对可安全隔离的部分提供防护。
- **应用自家的广告与统计。** 写在应用自有代码里、或由服务器在普通内容中混排的广告与统计，无法与功能区分，不在拦截范围内。
- **加密载荷。** 模块按通道拦截，不查看也不修改内容；一个必须保留的服务里夹带的数据，无法单独剔除。
- **识别盲区。** 加固或加密的安装包、运行时下发的代码可能无法被识别。
- **服务器端。** 服务端根据 IP、账号等进行的关联分析，以及服务器下发的新地址与配置，不在手机端可控的范围内。
- **你主动授权的能力。** 定位、通讯录、无障碍等权限一旦授予，应用就拥有相应能力，模块不会代替你做决定。
- **必须保留的服务。** 推送、支付、账号、系统更新等需要保持可用，其中夹带的数据无法单独剔除。
- **持续变化。** 厂商更新接口、SDK 更换通道，都会让规则过时。规则健康检测会提示失效或待复核，**诊断模式**则能记录已启用防护应用的网络请求并标出疑似新通道，导出不含个人信息的报告，帮助我们一起发现并补充新的规则。

隐私保护没有一劳永逸的办法：系统限制、用户授权、模块拦截各管一段，叠加起来才更可靠。如果你发现了新的收集渠道，欢迎通过诊断报告告诉我们。
